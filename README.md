# 巡演舞台调度与走位编排工作台

面向剧院巡演团队的舞台执行工作台，覆盖演员与道具调度、舞台走位、执行提示、留言协同、版本回退、基线锁定和演出文档打印。

## 技术栈

Vue 3 + Element Plus + Pinia + Vue Router + TanStack Query + Axios + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62044`。

## 核心工作流

- 在舞台平面图中选择走位，编辑入场点、退场点、路线节点和触发时机。
- 在同一脚本时间线中维护灯光、音响、道具与执行提示。
- 添加部门留言、标记问题并生成修改版本；撤销、重做和离线草稿会自动保存。
- 锁定演出基线，并从打印中心输出走位表和执行清单。

## 场次交接（离线 → 回网）

舞台监督和灯光师在转场途中离线带回的改动，通过「场次交接」台与主控版本收敛：

1. **离线队列**：离线期间对提示的修改按提示编号入队（同一编号多次改动合并为一条）。
2. **按编号三路合并**：回网时以最后同步版本为基准做三路合并——
   - 仅离线改过：离线版本生效；
   - 仅主控改过：并入主控版本（若覆盖时间/路线/部门，确认立即失效）；
   - **两边都改过**：同一编号保留主控、离线两份待处置，处置并重新确认前不进基线、不进打印清单。
3. **确认签名**：每条已确认提示保存 `时间|部门|路线` 签名；时间、路线或部门一旦再改，确认立即失效并写入交接记录，需重新确认。
4. **锁定基线与打印清单**：只有有效确认且无待处置冲突的提示可锁定为带基准号（`BL-日期-序号`）的基线快照；打印表/CSV 始终取自该快照，解锁或关键内容变更后标记失效、重锁重算。
5. **失败恢复**：合并请求失败时自动回滚到「最后确认的提示」检查点，离线队列保留，可直接重试；路线节点、交接记录、冲突对均做去重，不会重复追加。
6. **旧数据迁移**：检测到没有基准号的旧工作台数据（v1 本地存档或手动导入）时迁移为「历史场次」归档，原始记录保留、不覆盖当前场次。

交接逻辑位于 `src/stores/workshop.ts`，Node 烟雾测试见 `scripts/smoke.ts`（可用 esbuild 打包后运行）。
